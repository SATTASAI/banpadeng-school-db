# จัดฐานการเรียนรู้ (ฝ่ายบริหารทั่วไป)

เมนู **ฝ่ายทั่วไป → จัดฐานการเรียนรู้** (`/learning-bases.html`) จัดนักเรียน ป.1–6 เข้าฐานการเรียนรู้รายปีการศึกษา

- รายชื่อนักเรียนดึงจากทะเบียนกลาง (`students` สถานะ `enrolled` ชั้น ป.1–6) ทุกครั้งที่เปิดหน้า
- ข้อมูลเก็บใน D1 ของ system: `learning_bases` (ฐานต่อปี: ชื่อ จำนวนรับ ชั้นที่รับ ลำดับ) และ `learning_base_members` (1 คน 1 ฐานต่อปี + ชั้น/ห้อง ณ ตอนจัด)
- แสดงผลเฉพาะ system — ระบบรายงานผลการเรียน (grades) ไม่อ่านตารางนี้
- ปีแรกใช้ชื่อฐานตั้งต้น 18 ฐานจากไฟล์รายชื่อปี 2569 · ปีใหม่คัดลอกฐานจากปีก่อน · แก้ชื่อ/จำนวนรับ/ชั้นที่รับ/เพิ่ม/ลบได้ที่แท็บ ตั้งค่าฐาน
- แก้ไขได้เฉพาะปีการศึกษาปัจจุบัน ปีก่อนดูอย่างเดียว

## สิทธิ์

- แก้ไข: สมาชิกฝ่ายบริหารทั่วไป (`department_staff` หรือช่องฝ่ายในทะเบียนบุคลากร) และ admin (superadmin/executive)
- ดูอย่างเดียว: ผู้ที่เห็นเมนูฝ่ายทั่วไป (เช่น ผอ./รอง ผอ.) · บัญชีผู้ชมภายนอกเข้าไม่ได้

## วิธีจัดอัตโนมัติ (`src/lib/learning-base-assign.js`)

| วิธี | ความหมาย |
| --- | --- |
| `balanced` | คละชั้น ห้อง และเพศ ให้ทุกฐานเท่ากัน |
| `random` | สุ่มเท่ากันทุกฐาน ไม่สนชั้น/ห้อง |
| `by_grade` | ชั้นเดียวกันอยู่ฐานเดียวกันมากที่สุด |
| `whole_room` | ทั้งห้องเข้าฐานเดียวกัน ห้องที่ใหญ่เกินที่รับแบ่งไปฐานถัดไป |
| `keep_previous` | คงฐานเดิมจากปีก่อน (จับคู่ชื่อฐาน) แล้วคละคนที่เหลือ |

- ทุกวิธีเคารพจำนวนรับและชั้นที่ฐานรับ แล้วซ่อมคนที่ยังไม่มีที่ด้วยการย้ายคนในฐานที่เต็มไปฐานอื่นที่ว่าง
- ขอบเขต: จัดใหม่ทั้งหมด หรือจัดเฉพาะคนที่ยังไม่มีฐาน · "คงคนที่จัดเองไว้" = ไม่ทับรายการที่เปลี่ยนรายคน (`locked=1`)
- ดูตัวอย่างก่อนบันทึก ผลสุ่มผูกกับ `seed` จึงบันทึกได้ตรงกับตัวอย่าง

## API

- `GET /api/learning-bases?academic_year=2569`
- `PUT /api/learning-bases/bases` `{academic_year, bases:[{id?, name, capacity, grades}]}` — ฐานที่ไม่อยู่ในรายการ = ปิด (นักเรียนในฐานนั้นกลับเป็นยังไม่มีฐาน)
- `POST /api/learning-bases/auto` `{academic_year, method, scope, keep_locked, seed, apply}`
- `PUT /api/learning-bases/members` `{academic_year, student_id, base_id|null, force}` — ฐานเต็มตอบ 409 เว้นแต่ `force`
