# เอกสารโครงการและการเบิกจ่าย

เจ้าของโครงการเพิ่ม/แก้ไขรายละเอียดในหน้าฝ่ายงาน และเลือกประเภทเงิน: `subsidy` งบอุดหนุน, `free_education` งบเรียนฟรี 15 ปี หรือ `school_income` งบรายได้สถานศึกษา โครงการเดิมที่ยังไม่ระบุจะอยู่ในยอดแยก ไม่จัดประเภทให้โดยอัตโนมัติ

## เมนู (ปรับ 22 ต.ค. 2569)

- **ระบบสนับสนุน › ขอเบิกจ่ายและจัดซื้อจัดจ้าง** (`/finance-requests.html`) — ครูทุกคน: ยื่นขอเบิกจ่าย (`/project-documents.html`), ติดตามจัดซื้อจัดจ้าง, คำขอใช้งบแบบลงนามเดิม และสถานะคำขอของฉัน
- **ฝ่ายงบประมาณ › บันทึกเบิกจ่ายและจัดซื้อจัดจ้าง** (`/finance-register.html`) — ทะเบียนรับเรื่องคำขอทุกโครงการในรายการเดียว กรองตามขั้น (รอรับเรื่อง / กำลังดำเนินการ / รอผู้อำนวยการ / รอยืนยันเบิกจ่าย / ยืนยันแล้ว / ส่งกลับ-ไม่อนุมัติ)
  ปุ่ม รับเรื่อง · ตรวจแล้วเสนอผู้อำนวยการ · ผู้อำนวยการอนุมัติ · ยืนยันการเบิกจ่าย · ส่งกลับ · ไม่อนุมัติ ใช้ API และสิทธิ์เดิมทุกขั้น
  แท็บ "งานจัดซื้อจัดจ้าง" และ "ทะเบียนเบิกจ่าย (แบบลงนามเดิม)" อยู่ในหน้าเดียวกัน · ตัวเลขสีแดงที่เมนูคือจำนวนคำขอรอรับเรื่อง

เปิด `/project-documents.html` จากหน้าฝ่ายงานหรือเมนูระบบสนับสนุน ข้อมูลโครงการ ฝ่าย ผู้รับผิดชอบ ปีงบประมาณ และประเภทเงินใช้ข้อมูลกลาง กรอกวัตถุประสงค์ เหตุผล วันที่ และรายการค่าใช้จ่ายเอง บันทึกร่างและส่งเอกสารเป็นคนละสถานะ

## ขั้นตอนคำขอใหม่

1. `draft`: บันทึกร่าง ไม่มีการกันวงเงิน
2. `finance_queue`: ส่งเอกสารแล้ว แจ้งเจ้าหน้าที่และกันวงเงิน
3. `finance_processing`: เจ้าหน้าที่รับเรื่อง
4. `finance_ready`: ดำเนินการเสร็จสิ้น รอยืนยัน
5. `completed` / `paid`: ยืนยันการเบิกจ่าย ปรับยอดใช้จริงและแจ้งเจ้าของโครงการ

ฝ่ายงบประมาณมีแท็บโครงการภายในฝ่าย และโครงการฝ่ายอื่น ๆ ซึ่งรวมโครงการทั้งโรงเรียน โครงการที่มีคำขอใหม่เรียงก่อน ตามความสำคัญ วันที่ต้องการเงิน และลำดับส่ง แสดงตัวเลขแจ้งเตือนสีแดง เจ้าหน้าที่การเงินที่กำหนดใน `finance_review` และผู้บริหารสามารถรับเรื่อง ดำเนินการ ส่งกลับ ไม่อนุมัติ และยืนยันเบิกจ่ายได้

## ยอดเงิน

- เงินคงเหลือ = วงเงินจัดสรรโครงการ − ยอดยืนยันเบิกจ่ายทั้งหมด
- วงเงินที่ขอได้ = เงินคงเหลือ − ยอดคำขอที่รอดำเนินการ
- ยอดแยกประเภทเงินบน dashboard และฝ่ายงบประมาณมาจากฟังก์ชันเดียวกัน รวมวงเงินโครงการในปีงบประมาณที่เลือก ใช้ยอดก่อนหักภาษีเป็นยอดใช้จริง
- รายรับที่บันทึกเป็นข้อมูลอีกส่วนหนึ่ง ไม่เพิ่มวงเงินจัดสรรโครงการโดยอัตโนมัติ
- ห้ามยืนยันซ้ำ แก้ยอดรายการที่จ่ายแล้ว หรือลดวงเงินต่ำกว่ายอดผูกพันและใช้จริง
- ประเภทเงินเปลี่ยนไม่ได้หลังมีรายการผูกพัน/จ่ายแล้ว ยกเว้นการระบุครั้งแรกให้โครงการเดิมที่ยังไม่มีประเภท

## เอกสารเพิ่มเติม

เพิ่มได้ก่อนหรือหลังส่ง/ยืนยันคำขอ แต่ละไฟล์สร้างทะเบียนเอกสารใหม่ในคลังเอกสารและใช้การจัดเก็บ Google Drive เดิม ไม่แทนที่ไฟล์ก่อนหน้า แจ้งเจ้าหน้าที่เมื่ออัปโหลดสำเร็จ มีการกู้การแจ้งเตือนอัตโนมัติหากบันทึกไฟล์สำเร็จแต่การแจ้งเตือนขัดข้อง เจ้าของ ผู้รับผิดชอบร่วม เจ้าหน้าที่การเงิน และผู้บริหารเปิดเอกสารได้

API เดิมสำหรับแก้/สร้างรายการเบิกจ่ายโดยตรงจากหน้าฝ่ายงานไม่รับคำขอใหม่ รายการเก่าที่เริ่มกระบวนการลงนามแล้วดำเนินการต่อด้วยขั้นตอนเดิม คำขอใหม่ใช้ `workflow_version=2` มีการอัปเกรด schema แบบเพิ่มคอลัมน์และตาราง ไม่ลบข้อมูลเดิม

## ตรวจสอบ

`node --test tests/*.test.mjs` และ `python -m unittest discover -s tests -p 'test_*.py'`

ทดสอบวงจรคำขอ การกดยืนยันซ้ำ การส่งพร้อมกันเกินวงเงิน ส่งกลับ/ส่งใหม่ ผู้รับผิดชอบหลายคน เอกสารเพิ่มภายหลัง สิทธิ์ผู้ใช้ ตัวอัปโหลด Drive เดิม และยอดแยกทั้งสามประเภท

## ปีงบประมาณเริ่มต้นกับปีการศึกษา

ปฏิทินงบประมาณขึ้นปีใหม่ 1 ต.ค. ซึ่งตรงกับช่วงเปิดภาคเรียนที่ 2 ระบบจึงใช้ **"ปีงบประมาณที่ใช้งาน"** (`workingFiscalYear` ใน `src/lib/project-finance.js`, API `GET /api/projects/working-year`) เป็นค่าเริ่มต้นแทนปีตามปฏิทิน:

- ถ้ามีโครงการในปีการศึกษาปัจจุบันที่ปีงบประมาณตรงกับปีการศึกษา → ใช้ปีนั้น (เช่น ปีการศึกษา 2569 → 2569 จนถึง มี.ค. 2570)
- ไม่เช่นนั้นใช้ปีงบประมาณล่าสุดของโครงการในปีการศึกษาปัจจุบัน และถ้ายังไม่มีโครงการเลยจึงใช้ปีตามปฏิทิน

ใช้กับ: หน้าฝ่ายงบประมาณ (ทุกมุมมอง/รายงาน), จัดซื้อจัดจ้าง, การเพิ่มโครงการใหม่ (หน้าฝ่ายงาน และหน้าโครงการในฝ่าย) — เลือกปีอื่นจากตัวเลือกปีได้ตามเดิม
ยอดคงเหลือโครงการคิดตลอดอายุโครงการ ไม่ตัดตามปีงบประมาณ และการเปลี่ยนภาคเรียนไม่ล็อกการแก้ไข/เบิกจ่ายของโครงการ
