# แจ้งเตือนทาง LINE รายบุคคล

โค้ด: `src/lib/line-feed.js` (ส่ง) · `src/routes/notifications.js` (รายการเดียวกับกระดิ่ง) · งานแจ้งซ่อมส่งเองใน `src/index.js`

## ขั้นตอน

1. แอดมินจับคู่บัญชี LINE กับครูที่หน้า ตั้งค่า LINE (หรือครูเชื่อมเองด้วยรหัส `BPD-xxxxxx` ในหน้าบัญชี)
2. รอบแรกหลังจับคู่: จดรายการเก่าที่ค้างอยู่ไว้ ไม่ส่งย้อนหลัง แต่ส่งใบลาที่สร้างหลังเวลาเชื่อม LINE แม้รอบส่งครั้งแรกเพิ่งทำงาน
3. หลังมีการบันทึกข้อมูลสำเร็จ (POST/PATCH/PUT/DELETE ของ `/api/`) ระบบเริ่มรอบส่งทันทีเบื้องหลัง เว้นระยะอย่างน้อย 15 วินาที; Cron ทุก 2 นาทีเก็บตกที่เหลือ
4. แต่ละรอบ ต่อครูหนึ่งคน: ดึงรายการแจ้งเตือน → ตัดที่ส่งแล้ว/เก่ากว่า 72 ชม./ตัวเองเป็นคนทำ/เป็นรายการกำกับดูแล → รวมเป็น 1 ข้อความ → ส่ง → จดว่าส่งแล้ว ข้อความที่ LINE ตอบว่าล้มเหลวจะลองซ้ำหลังอย่างน้อยหนึ่งนาที
5. ถ้าอ่านเรื่องทั่วไปในระบบก่อนรอบส่ง จะไม่ส่ง LINE แต่ใบลายังคงส่งแม้เปิดอ่านกระดิ่งแล้ว · ครูปิดรับได้ในหน้าบัญชี · โควตาเหลือ ≤ 20 ข้อความหยุดส่ง (เก็บไว้ให้งานซ่อม)

## ใครได้รับ LINE

| เหตุการณ์ | ได้รับ LINE |
|---|---|
| ครูส่งคำขอเบิก | เจ้าหน้าที่การเงิน (ถ้ายังไม่ตั้ง → ผู้ดูแลระบบ) |
| การเงินรับเรื่อง / ยืนยันจ่าย / ส่งกลับ | เจ้าของโครงการ |
| การเงินเสนออนุมัติ | ผู้อำนวยการ |
| ผอ. อนุมัติเบิก / เจ้าของปิดยอด / แนบเอกสารเพิ่ม | เจ้าหน้าที่การเงิน |
| ส่งรายงานขอซื้อ/จ้าง | หัวหน้าเจ้าหน้าที่พัสดุ (ไม่มี → ผอ.) |
| หัวหน้าเห็นชอบ | ผอ. |
| ผอ. อนุมัติจัดซื้อ | เจ้าหน้าที่พัสดุ + ผู้ตรวจรับทุกคน |
| บันทึกส่งมอบ | ผู้ตรวจรับทุกคน |
| ไม่รับพัสดุ / ส่งกลับ / ยกเลิก | เจ้าหน้าที่พัสดุ (ยกเลิก: + การเงิน) |
| ตรวจรับครบ | เจ้าหน้าที่พัสดุ, การเงิน, เจ้าของโครงการ (แจ้งให้ปิดยอดถ้ายอดจริงน้อยกว่า) |
| ครูยื่นลา | หัวหน้าฝ่ายบุคลากร และรองผู้อำนวยการที่รับผิดชอบฝ่ายบุคลากร (รองได้รับแจ้งเพื่อทราบ ยังทำรายการไม่ได้) |
| หัวหน้าส่งต่อ | รองผู้อำนวยการที่เลือก (เริ่มมีสิทธิ์บันทึกความเห็น) |
| รองบันทึกความเห็น | ผู้อำนวยการ |
| ผลการลา | ครูผู้ลา |
| มอบหมายงาน | ผู้รับมอบหมาย (ไม่ส่งถ้ามอบให้ตัวเอง) |
| จัดสอนแทน | ครูผู้สอนแทน (เฉพาะวันนี้เป็นต้นไป, ต้องผูกบัญชีกับทะเบียนบุคลากร) |
| มอบหมายหนังสือราชการ | ผู้รับมอบหมาย |
| คำขอแก้ยอดใช้ไปแล้ว | ผู้บริหารและผู้ดูแลระบบ (รอพิจารณา) / ผู้ขอ (ผล) |
| ขอลบนักเรียนถาวร | ผอ. (รอพิจารณา) / ผู้ขอ (ผล) |
| แจ้งซ่อมใหม่ / มอบหมายช่าง / ซ่อมเสร็จ | หัวหน้าฝ่ายบริหารทั่วไป (แทนกลุ่ม LINE โรงเรียน; ถ้ายังไม่ตั้งหัวหน้าฝ่าย จะส่งเข้ากลุ่มเหมือนเดิม) |
| มอบหมายช่าง / ผู้แจ้งตรวจรับ | ช่างที่รับผิดชอบ |
| เริ่มซ่อม / รออะไหล่ / ซ่อมเสร็จ / ยกเลิก | ผู้แจ้ง |

หัวหน้าฝ่ายบริหารทั่วไป (ตั้งที่หน้ารายชื่อบุคลากรฝ่ายบริหารทั่วไป และต้องผูกบัญชีกับทะเบียนบุคลากร) มีสิทธิ์จัดการงานซ่อมเหมือนเจ้าหน้าที่ เพื่อรับเรื่องและมอบหมายช่างได้

รายการที่ผู้บริหารหรือผู้ดูแลระบบเห็นเพื่อกำกับดูแล (คิวการเงินทั้งหมด, ใบลาทั้งหมด) ยังขึ้นที่กระดิ่งในระบบ แต่ไม่ส่ง LINE
รองได้รับแจ้งโดยใช้ผู้รับผิดชอบใน `leave_settings` จากหน้าระบบการลา หากยังไม่ได้ตั้ง จะอ้างอิงบทบาท `deputy_director` ของฝ่าย `personnel` หรือรองผู้บริหารเพียงท่านเดียวที่ active; ถ้ามีหลายท่านแต่ไม่กำหนดผู้รับ ระบบจะไม่ส่งล่วงหน้าให้รองคนใดเพื่อป้องกันการแจ้งผิดคน รองดูข้อมูลได้แบบอ่านอย่างเดียวจนกว่าหัวหน้าฝ่ายจะส่งต่อ จึงบันทึกความเห็นได้

หากบุคลากรคนเดียวกันมีหลายบัญชีในระบบ การส่ง LINE ใช้รายการจับคู่เดิมจากบัญชีใดบัญชีหนึ่งที่ผูกกับ `personnel_accounts` เดียวกัน โดยไม่ต้องเชื่อมซ้ำ; ถ้ามี LINE ID หลายค่าที่ขัดแย้งกันจะไม่เดาผู้รับ และถ้าสองบัญชีเห็นแจ้งเตือนเดียวกันจะส่งหา LINE ID นั้นเพียงครั้งเดียว การเข้ากลุ่ม LINE อย่างเดียวไม่ใช่การจับคู่รายบุคคลและไม่รับประกัน Push แบบส่วนตัว
ผอ. ไม่ได้ LINE ตอนใบลาเพิ่งส่งต่อ (ยังต้องรอรองบันทึกความเห็น) จะได้เมื่อถึงคิวออกคำสั่ง

## ความทนทาน (ปรับ 21 ต.ค. 2569)

- **รอบส่ง**: ประมวลผลผู้รับพร้อมกันครั้งละ 6 คน (บัญชีที่ใช้ LINE ID เดียวกันทำตามลำดับเพื่อส่งครั้งเดียว) · ล็อกถือไว้จนรอบจบ ไม่ให้รอบใหม่ทับ (รอบที่ค้างปล่อยหลัง 5 นาที) · รอบที่เริ่มหลังการบันทึกข้อมูลทำงานไม่เกิน 20 วินาที คนที่เหลือรอ Cron ถัดไป (บันทึกใน note ของรอบ)
- **LINE API**: ทุกคำขอหมดเวลาใน 10 วินาที · push แนบ `X-Line-Retry-Key` ที่คงที่ต่อ (ผู้รับ + ชุดรายการ) ถ้า LINE รับไปแล้วแต่คำตอบหาย การลองใหม่จะได้ 409 และถือว่าส่งแล้ว ไม่ส่งซ้ำ
- **ล้มเหลว**: 4xx (ยกเว้น 429) = ถาวร บันทึก `skipped` ไม่ลองซ้ำ · หมดเวลา/5xx/429 = `failed` ลองใหม่รอบถัดไป (ภายใน 72 ชม.)
- **Webhook**: เหตุการณ์จากแชต 1:1 และเข้า/ออกกลุ่มบันทึก `webhook_event_id` ก่อนประมวลผล เหตุการณ์ที่ LINE ส่งซ้ำจึงทำครั้งเดียว · ข้อความทั่วไปในกลุ่มไม่บันทึก event และอัปเดตปลายทางไม่เกินชั่วโมงละครั้ง
- **ล้างข้อมูล (รอบ Cron)**: `line_webhook_events` > 30 วัน, `leave_line_access` หมดอายุ > 1 วัน, `line_link_failures` > 1 วัน, `line_feed_sent` > 90 วัน
- **แจ้งซ่อม**: ยังแสดงผลการส่งทันทีหลังบันทึก แต่ส่งถึงผู้รับทุกคนพร้อมกัน (จองโควตาก่อน) · ลิงก์และรูปในข้อความใช้โดเมน `system.banpadengschool.ac.th` เสมอ (หรือ `PUBLIC_BASE_URL`)
- **เชื่อมบัญชีด้วยรหัส**: บัญชีที่ถูกลบแล้วใช้รหัสเชื่อม LINE ไม่ได้
