# ใบลาและขั้นตอนส่งต่อ

เมนู **ฝ่ายบริหาร → อนุมัติการลา** (`/leave.html?view=approval`) แสดงใบลาทุกสถานะจากทะเบียน leave_requests ชุดเดียวกับฝ่ายบุคคล รวมรายการเดิมก่อนมีขั้นตอนส่งต่อ ทั้งรอรับทราบ รอส่งต่อ รออนุมัติ และประวัติอนุญาต/ไม่อนุญาต โดยไม่คัดลอกข้อมูลหรือเปลี่ยนผลพิจารณา แอดมิน (superadmin) ผอ. และรอง ผอ. ที่มีทะเบียนและบัญชีผู้บริหาร active ดูรายละเอียดและดาวน์โหลดใบลาได้ API ส่ง can_view_all_leave เพื่อควบคุมการแสดงหน้านี้ ผู้ใช้ทั่วไปยังเห็นเฉพาะใบลาตามสิทธิ์เดิม

แอดมินและรอง ผอ. เริ่มต้นดูได้อย่างเดียว ผอ. คนปัจจุบันเท่านั้นมอบและถอนสิทธิ์อนุมัติให้รอง ผอ. เป็นรายคนได้ในหน้านี้ (`GET/PATCH /api/leave-delegations`) ผู้ดูแลระบบหรือหัวหน้าฝ่ายบุคคลไม่ได้สิทธิ์อนุมัติหรือมอบหมายโดยอัตโนมัติ ปุ่มรับทราบของฝ่ายบุคคล/ยกเลิกใช้จากหน้าการลาเดิม

ผอ. หรือรอง ผอ. ที่ได้รับมอบสิทธิ์กด **รับทราบและอนุมัติ** (`PATCH /api/leave-requests/:id` action `acknowledge_approve`) ได้กับใบลา pending ทั้ง submitted, acknowledged และ forwarded รวมรายการเดิมที่ยังไม่ได้ส่งต่อ ระบบรับทราบและอนุมัติในธุรกรรมเดียว เปลี่ยนเป็น approved/completed บันทึกผู้พิจารณา เวลา เหตุการณ์ และ audit log พร้อมนำไปนับสถิติและแจ้งผู้ยื่นใบลา เก็บผู้รับทราบ/เวลารับทราบเดิมไว้หากมีอยู่ ไม่สร้างประวัติส่งต่อที่ไม่ได้เกิดขึ้นจริง การกดซ้ำหรืออนุมัติพร้อมกันไม่เพิ่มผลหรือสถิติซ้ำ และห้ามอนุมัติใบลาตนเองรวมบัญชีที่ผูกบุคลากรเดียวกัน สิทธิ์มอบหมายตรวจซ้ำขณะบันทึก ปุ่มไม่อนุญาตและ API decide เดิมยังใช้เฉพาะใบลาที่ส่งต่อแล้ว

โหมด **ดูในมุมมองบัญชีอื่น (view as)** แสดงปุ่มรับทราบและอนุมัติเป็นตัวอย่างที่กดไม่ได้ พร้อมข้อความให้เข้าสู่ระบบด้วยบัญชีผู้มีสิทธิ์เพื่ออนุมัติจริง ระบบยังปฏิเสธการเขียนทุกช่องทางในโหมดนี้

สิทธิ์เก็บตามทะเบียนบุคลากรใน leave_approval_delegations และมีบันทึกผู้มอบ เวลา และประวัติมอบ/ถอนใน audit_logs การเลือกผู้รับแจ้งเตือน LINE เดิมไม่ใช่การมอบสิทธิ์อนุมัติ เมื่อถอนสิทธิ์มีผลกับรายการที่ยังรออนุมัติทันที ระบบตรวจบทบาทและตำแหน่งปัจจุบันทุกครั้ง และตรวจสิทธิ์มอบหมายซ้ำขณะเปลี่ยนสถานะใบลา รอง ผอ. ที่ได้รับสิทธิ์อนุญาต/ไม่อนุญาตได้เช่นเดียวกับ ผอ. พร้อมบันทึกชื่อและตำแหน่งผู้พิจารณาจริง ห้ามอนุมัติใบลาตนเองรวมบัญชีที่ผูกบุคลากรเดียวกัน และไม่เปลี่ยนผลพิจารณาเก่า

หัวหน้าฝ่ายบุคลากรหรือผู้ดูแลระบบตั้งจำนวนครั้งการลาต่อคนต่อเทอมได้ที่หน้าใบลา (PATCH /api/leave-settings โดยส่ง limits ครบสองกลุ่ม general และ lenient) ค่าเริ่มต้นลาทั่วไปรวมทุกประเภทยกเว้นลาอนุโลม 2 ครั้ง และลาอนุโลมแยกอีก 2 ครั้งต่อเทอม เว้นว่างหมายถึงไม่จำกัด และ 0 หมายถึงไม่ให้ยื่นกลุ่มนั้น เงื่อนไขใหม่เก็บใน leave_term_limits แยกจากเงื่อนไขรายปีเดิม และไม่เปลี่ยนผลใบลาเดิม

เมื่อเปิดหน้าและเปลี่ยนวันที่เริ่มลา ระบบแสดงสิทธิ์ผ่าน GET /api/leave-allowance?date=YYYY-MM-DD โดยอ้างอิงภาคเรียนจากวันเริ่มลาและปฏิทินปีการศึกษาจริง นับประวัติตามช่วงวันที่เริ่ม–สิ้นสุดเทอม รวมบัญชีที่ผูกบุคลากรเดียวกัน ใบละหนึ่งครั้ง รายการรอพิจารณากันสิทธิ์ไว้ และคืนเมื่อไม่อนุญาตหรือยกเลิก ระบบตรวจเงื่อนไขขณะบันทึกเพื่อป้องกันคำขอพร้อมกันเกินสิทธิ์ หากไม่พบเทอมหรือปฏิทินซ้อนกันจะให้ผู้รับผิดชอบตรวจปฏิทินก่อนยื่น สถิติในใบดาวน์โหลดคงปีงบประมาณตามแบบเดิม

ครูกรอกเหตุผลการลาทุกประเภท พร้อมตำแหน่ง วันที่เขียน วันเริ่มและสิ้นสุด จำนวนวันลา ที่อยู่ระหว่างลา และเบอร์ติดต่อ แล้วส่งคำขอถึงหัวหน้าฝ่ายบุคลากร หัวหน้าฝ่ายตรวจข้อมูลและกด **รับทราบและส่งต่ออัตโนมัติ** ครั้งเดียว ระบบบันทึกการรับทราบและส่งข้อมูลพร้อมแจ้งเตือนถึงผู้อำนวยการกับรองผู้อำนวยการที่รับผิดชอบในรายการเดียวกัน รอง ผอ. ดูข้อมูลเพื่อทราบ ผอ. เป็นผู้อนุมัติหรือไม่อนุมัติได้ทันที ไม่มีขั้นตอนรอความเห็นจากรอง ผอ.

หัวหน้าฝ่ายอ้างอิงจาก department_staff.is_head ของฝ่าย personnel และบัญชีที่ผูกทะเบียนบุคลากร ผู้ดูแลระบบตรวจทะเบียนและตั้งค่าได้ แต่ไม่อนุมัติแทน ผอ. หัวหน้าฝ่ายหรือแอดมินกำหนดรองผู้รับผิดชอบผ่านหน้าใบลาหรือ PATCH /api/leave-settings หากยังไม่กำหนดใช้บทบาทรองฝ่ายบุคลากรหรือรองที่ active เพียงคนเดียว ผอ. ต้องมีหนึ่งท่านและมีบัญชีผู้บริหาร active ผู้รับผิดชอบต้องเชื่อม LINE จึงรับข้อความส่วนตัวได้ หากข้อมูลผู้รับไม่ครบ การรับทราบจะไม่บันทึกค้างครึ่งขั้นตอน และแจ้งให้แก้ทะเบียนก่อน

สถานะใหม่ submitted → forwarded → completed โดยการกดรับทราบบันทึก acknowledged และ forwarded events พร้อมผู้รับและชื่อผู้บริหารในฐานข้อมูลเดียวกัน รายการเดิม acknowledged แสดงปุ่มรับทราบและส่งต่อเพื่อดำเนินการต่อได้ และคงผู้รับทราบกับวันที่เดิม ใบเดิม forwarded ให้ ผอ. อนุมัติได้ทันทีแม้ยังไม่มีความเห็นรอง ผอ. ประวัติความเห็นเดิมยังแสดงในเอกสาร การกดซ้ำหรือพร้อมกันไม่สร้างเหตุการณ์หรือผู้รับซ้ำ ครูยกเลิกได้ก่อนรับทราบเท่านั้น และ ผอ. อนุมัติใบลาของตนเองไม่ได้ รวมถึงบัญชีอื่นที่ผูกบุคลากรเดียวกัน

เมื่อ ผอ. อนุมัติหรือไม่อนุมัติ ระบบบันทึกผู้พิจารณา วันที่และผลการพิจารณา แจ้งผู้ยื่นลา และนำเฉพาะใบที่อนุมัติไปคำนวณสถิติการลาที่อนุมัติแล้ว รายการรอพิจารณายังคงกันโควตาต่อเทอม และคืนสิทธิ์เมื่อไม่อนุมัติหรือยกเลิกตามเงื่อนไขข้างต้น

Word/PDF ใช้แบบใบลาป่วย ลาคลอดบุตร ลากิจส่วนตัวตามภาพที่ผู้ใช้ส่งวันที่ 6 ตุลาคม 2569 มีสถิติหกช่อง ผู้ตรวจสอบ ความเห็น และคำสั่ง พร้อมชื่อผู้รับผิดชอบจากทะเบียนเมื่อส่งต่อ ไม่ใส่ตราครุฑในใบลาแบบนี้ ช่องลายเซ็นใช้ภาพพื้นใสจากคลังกลางเมื่อมีข้อมูล โดยบันทึกสำเนาของครูตอนส่งคำขอ และสำเนาผู้อนุมัติ/รองฝ่ายบุคคลตอนอนุมัติ ไม่ประทับลายเซ็นผู้บริหารในใบลาที่ยังรอพิจารณา

การลาครั้งล่าสุดและสถิติใช้รายการอนุมัติของบุคลากรเดียวกัน รวมบัญชีเก่าที่ผูกทะเบียนเดียวกัน สถิติใช้ปีงบประมาณตามวันที่เริ่มลา จำนวนวันระบุได้ทีละครึ่งวัน สถิติ Dashboard ใช้จำนวนวันจริงที่บันทึก และแบ่งตามสัดส่วนช่วงวันที่เมื่อรายการคร่อมปีงบประมาณ รายการเก่าที่ไม่เคยระบุจำนวนวันใช้จำนวนวันตามช่วงวันที่เดิม

Migration เพิ่มคอลัมน์และตารางตอนใช้ API โดยไม่ลบใบลาเดิม รายการเดิมที่ยัง pending เข้าคิวให้หัวหน้าฝ่ายรับทราบ ส่วนข้อมูลเก่าที่ไม่มีเหตุผลหรือที่อยู่แสดงช่องว่างตามจริงในไฟล์

## การนับวันลา

นับเฉพาะวันจันทร์ถึงศุกร์ หักวันหยุดราชการและวันหยุดชดเชย รวมวันหยุดจาก `gr_holidays` ทุกปีการศึกษา (ไม่หักรายการชนิด `activity`) ใช้ API `/api/leave-working-days?start=YYYY-MM-DD&end=YYYY-MM-DD` สำหรับแบบฟอร์ม และตรวจจำนวนอีกครั้งก่อนบันทึก ไม่รับคำขอที่มีแต่วันหยุด ยังคงรองรับครึ่งวัน

ทะเบียน ใบลาส่งออก และสถิติใช้การคำนวณเดียวกันกับใบลาเดิม โดยไม่เขียนทับยอดต้นฉบับหรือประวัติอนุมัติ: ยอดที่เกินวันทำงานถูกจำกัดตามวันทำงาน ยอดที่เคยระบุลดลงยังคงเดิมและคงเศษครึ่งวัน การแบ่งยอดระหว่างช่วงสถิติใช้สัดส่วนวันทำงานในแต่ละช่วง เพราะข้อมูลเดิมไม่ได้ระบุว่าครึ่งวันอยู่วันใด จำนวนครั้งยังนับตามใบลาเดิม

## ลายเซ็นและการแยกประเภทใบลา

หน้าการลามีการ์ดลาจริงและลาอนุโลมแยกทะเบียน/รายการรอดำเนินการ ลาจริงรวมเฉพาะสถิติปีงบประมาณ ลาอนุโลมเก็บประวัติและยอดแยก ไม่บวกในจำนวนครั้ง/วันอนุมัติประจำปีงบประมาณหรือกราฟรายเดือนของลาจริง เงื่อนไขจำนวนครั้งต่อภาคเรียนยังแยกสองกลุ่มเหมือนเดิม

ครูอัปโหลดลายเซ็นตนเองที่หน้าการลา แอดมินอัปโหลดลายเซ็นบัญชีผู้อนุมัติที่กำหนดไว้ในหน้าตั้งค่าผู้อนุมัติ ระบบตัดกระดาษสีขาว/เทาในเบราว์เซอร์ มีตัวปรับความไวและตัวอย่างพื้นใสก่อนบันทึก รับภาพ PNG/JPG/WebP ไม่เกิน 5 MB จัดเก็บ PNG พื้นใสไม่เกิน 400 KB ใน teacher_signatures ใช้ร่วมกับงานส่งของครูและงานอื่นผ่าน API /api/signatures (private, no-store) ไม่เปิดอ่านลายเซ็นของผู้อื่นแก่ครูทั่วไป การแก้ไขมี audit และโหมดดูบัญชีอื่นยังอ่านอย่างเดียว

ใบลาเก็บภาพลายเซ็นเป็นสำเนาตามขั้นตอน โดยช่องผู้อนุมัติใช้ผู้กดอนุมัติจริง (รวมรองที่ได้รับสิทธิ์) ช่องรองฝ่ายบุคคลใช้บุคลากรผู้รับผิดชอบใบลาที่กำหนดไว้ ไม่สร้างเหตุการณ์หรือเวลาให้ความเห็นแทนรอง ลายเซ็นที่เปลี่ยนภายหลังไม่เปลี่ยนสำเนาในใบลาเดิม รายการเก่าที่ไม่มีสำเนาจะคงช่องลงชื่อว่าง ไม่ประทับย้อนหลังอัตโนมัติ

หมายเหตุเป็นข้อมูลจากผู้ยื่น แยกจากความเห็นบุคลากร/ผู้อนุมัติ ลาอนุโลมใหม่ต้องกรอกชื่อผู้ได้รับมอบหมายคาบสอนแทนด้วยตนเอง ข้อมูลนี้พิมพ์ในใบลา ไม่ได้สร้างรายการจัดสอนแทนอัตโนมัติ Word/PDF ใช้ข้อมูลเต็มความกว้างพื้นที่พิมพ์ A4 ขอบซ้ายขวาเท่ากัน ตารางสถิติเต็มหน้า และฝังภาพลายเซ็นในไฟล์
