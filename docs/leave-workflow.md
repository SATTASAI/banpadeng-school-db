# ใบลาและขั้นตอนส่งต่อ

หัวหน้าฝ่ายบุคลากรหรือผู้ดูแลระบบตั้งจำนวนครั้งการลาต่อคนต่อประเภทได้ที่หน้าใบลา รวมลาอนุโลม (`PATCH /api/leave-settings` โดยส่ง `limits` ครบห้าประเภท) ค่าเริ่มต้นไม่จำกัด เว้นว่างหมายถึงไม่จำกัด และ 0 หมายถึงไม่ให้ยื่นประเภทนั้น เงื่อนไขใช้กับทุกคนในปีงบประมาณ 1 ตุลาคม–30 กันยายน โดยอ้างอิงวันที่เริ่มลา การปรับเงื่อนไขมีผลต่อการยื่นครั้งต่อไป ไม่เปลี่ยนผลใบลาเดิม

เมื่อเปิดหน้าและเปลี่ยนวันที่เริ่มลา ระบบแสดงสิทธิ์ผ่าน `GET /api/leave-allowance?date=YYYY-MM-DD` แยกจำนวนอนุมัติแล้ว รอพิจารณา และยื่นได้อีก นับใบละหนึ่งครั้ง รวมบัญชีที่ผูกทะเบียนบุคลากรเดียวกัน รายการรอพิจารณากันสิทธิ์ไว้จนกว่าจะถูกปฏิเสธหรือยกเลิก ไม่รวมรายการไม่อนุญาต ระบบตรวจเงื่อนไขกับประวัติปัจจุบันขณะบันทึกในฐานข้อมูลด้วย เพื่อป้องกันคำขอพร้อมกันเกินสิทธิ์ และแยกลาอนุโลมจากอื่น ๆ ด้วย subtype เดิม

ครูกรอกเหตุผลการลาทุกประเภท พร้อมตำแหน่ง วันที่เขียน วันเริ่มและสิ้นสุด จำนวนวันลา ที่อยู่ระหว่างลา และเบอร์ติดต่อ จากนั้นส่งให้หัวหน้าฝ่ายบุคลากร และแจ้ง LINE ล่วงหน้าให้รองฝ่ายบุคลากรที่กำหนดไว้ รองดูข้อมูลได้แบบอ่านอย่างเดียวจนกว่าหัวหน้าฝ่ายจะส่งต่อ

หัวหน้าฝ่ายกำหนดรองผู้รับแจ้งที่หน้าใบลา **ก่อนครูยื่นใบแรก** (`PATCH /api/leave-settings`) หรือผู้ดูแลระบบกำหนดผ่าน API ได้ ระบบแสดงสถานะเชื่อม LINE ของรองแต่ละคน หากยังไม่ได้กำหนด จะใช้รองที่ได้รับบทบาท `deputy_director` ของฝ่าย `personnel` หรือรองที่ active เพียงท่านเดียวเท่านั้น การกำหนดครั้งแรกเติมผู้รับให้ใบลาที่ยังค้างและยังไม่มีผู้รับ รองต้องผูกบัญชีผู้บริหารกับทะเบียนบุคลากร และเชื่อม LINE OA รายบุคคลก่อนจึงจะรับ Push ได้

หัวหน้าฝ่ายอ้างอิงจาก `department_staff.is_head` ของฝ่าย `personnel` และบัญชีที่ผูกกับทะเบียนบุคลากรจริง รับทราบและบันทึกข้อความก่อนส่งต่อได้ สามารถแก้บันทึกระหว่างที่ยังไม่ส่งต่อและดูทะเบียนย้อนหลังได้

ก่อนส่งต่อ หัวหน้าฝ่ายเลือกรองผู้อำนวยการที่ได้รับมอบหมายดูแลฝ่ายบุคลากร ระบบจำตัวเลือกหลังส่งสำเร็จ ผู้อำนวยการต้องมีเพียงหนึ่งท่านที่มีบัญชีผู้บริหาร active รองที่เลือกต้องมีตำแหน่งรองผู้อำนวยการและบัญชีผู้บริหาร active เช่นกัน หากทะเบียนไม่ครบ ระบบแจ้งให้ตรวจข้อมูลแทนการส่งไปให้ผู้บริหารทุกคน

การส่งต่อบันทึกผู้รับและแจ้งเตือนทั้งผู้อำนวยการกับรองที่เลือก รองบันทึกความเห็นก่อนผู้อำนวยการออกคำสั่งอนุญาตหรือไม่อนุญาต มีแจ้งเตือนรอบใหม่ถึงผู้อำนวยการหลังบันทึกความเห็น และถึงครูเมื่อมีผลพิจารณา ผู้ดูแลระบบตรวจทะเบียนได้ แต่ไม่ออกคำสั่งแทนผู้บริหาร

รายการใหม่ผ่านสถานะ `submitted → acknowledged → forwarded → completed` โดย `status` เดิมยังเป็น pending/approved/rejected เพื่อให้สถิติเดิมทำงานต่อได้ ทุกขั้นเก็บเหตุการณ์และ audit log การส่งซ้ำหรือสถานะเปลี่ยนระหว่างดำเนินการถูกปฏิเสธ การยกเลิกโดยครูทำได้ก่อนหัวหน้าฝ่ายรับทราบ การล้างข้อมูลทดสอบใช้ Avada เดิมซึ่งตรวจและเก็บความสัมพันธ์ของตารางลูกด้วย

Word/PDF ใช้แบบใบลาป่วย ลาคลอดบุตร ลากิจส่วนตัวตามภาพที่ผู้ใช้ส่งวันที่ 6 ตุลาคม 2569 มีสถิติหกช่อง ผู้ตรวจสอบ ความเห็น และคำสั่ง พร้อมชื่อผู้รับผิดชอบจากทะเบียนเมื่อส่งต่อ ไม่ใส่ตราครุฑในใบลาแบบนี้ ช่องลายเซ็นเว้นไว้สำหรับลงนาม

การลาครั้งล่าสุดและสถิติใช้รายการอนุมัติของบุคลากรเดียวกัน รวมบัญชีเก่าที่ผูกทะเบียนเดียวกัน สถิติใช้ปีงบประมาณตามวันที่เริ่มลา จำนวนวันระบุได้ทีละครึ่งวัน สถิติ Dashboard ใช้จำนวนวันจริงที่บันทึก และแบ่งตามสัดส่วนช่วงวันที่เมื่อรายการคร่อมปีงบประมาณ รายการเก่าที่ไม่เคยระบุจำนวนวันใช้จำนวนวันตามช่วงวันที่เดิม

Migration เพิ่มคอลัมน์และตารางตอนใช้ API โดยไม่ลบใบลาเดิม รายการเดิมที่ยัง pending เข้าคิวให้หัวหน้าฝ่ายรับทราบ ส่วนข้อมูลเก่าที่ไม่มีเหตุผลหรือที่อยู่แสดงช่องว่างตามจริงในไฟล์
