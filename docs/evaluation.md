# ระบบประเมินผลการปฏิบัติงาน

เว็บไซต์: `https://evaluate.banpadengschool.ac.th/` เมนูฝ่ายบริหาร → ประเมินผลการปฏิบัติงาน
ผลที่ยืนยันแล้ว: ฝ่ายบุคลากร → ประเมิน PA (`/evaluation-results.html`)

## โครงสร้างและการติดตั้ง

ระบบประเมินอยู่ใน repo เดียวกับระบบโรงเรียน: `src/evaluation/`, `public/evaluate.html`, `public/js/evaluation.js` และ CSS ของตนเอง
ใช้ Worker และ D1 เดียวกันเพื่อให้ผลในฝ่ายบุคลากรตรงกันทันที ไม่คัดลอกข้อมูลบุคลากร/คะแนนข้ามฐาน และไม่เพิ่มค่าใช้จ่าย Worker/ฐานข้อมูลอีกชุด
แยก hostname, หน้าเว็บ และ session ของแต่ละ hostname; `evaluate` ไม่เสิร์ฟ API/หน้าอื่นของโรงเรียน
บัญชีภายในใช้ชื่อผู้ใช้/รหัสผ่านเดิม แต่ต้องเข้าสู่ระบบใน hostname ประเมินต่างหาก ไม่ขยาย cookie ไปทั้งโดเมน

ตารางถูกสร้างอัตโนมัติเมื่อเรียก evaluation API ครั้งแรก ไม่เรียก migration ของงบประมาณ/ตารางเรียน/ระบบอื่น
`schema.js` เป็นแหล่งอ้างอิงตารางประเมิน; การสำรอง D1 เดิมครอบคลุมตารางนี้ด้วย
ตั้ง `assets.run_worker_first=true` เพื่อให้ทุกเส้นทางผ่านตัวตรวจ hostname ก่อนเสิร์ฟไฟล์
Workflow `Connect evaluation domain` เป็นคำสั่งติดตั้งโดเมนที่เรียกเองหลัง Worker deploy สำเร็จ โดยใช้ Cloudflare token (ต้องมี Workers Scripts Write) การทดสอบติดตั้งครั้งแรกได้ HTTP 403 จึงต้องเพิ่มสิทธิ์ที่ Cloudflare หรือผูก Custom domain ผ่านหน้า Worker Settings ด้วยบัญชีเจ้าของก่อน ไม่ลองซ้ำอัตโนมัติทุก deploy
ผูกเฉพาะ hostname ที่ขอ ไม่แก้ hostname โรงเรียนอื่น และหยุดหากชื่อที่ขอผูก Worker อื่นอยู่แล้ว

## ขั้นตอน

1. หัวหน้าฝ่ายบุคลากร/แอดมินตรวจแบบ ก.ค.ศ. และสร้างเกณฑ์รุ่นที่ยืนยันแล้ว
2. ผู้จัดรอบเลือกครู เกณฑ์ ปีงบประมาณ รอบ 1–4 วันที่ วิทยฐานะ ประเด็นท้าทายและลิงก์แฟ้มหลักฐาน
3. แต่งตั้งกรรมการให้ครบตามจำนวนในเกณฑ์ แล้วเปิดรอบ (หลังเปิดแก้รายชื่อ/เกณฑ์ไม่ได้)
4. กรรมการบันทึกร่างหรือส่งผล คะแนนต้องครบทุกข้อและอยู่ในช่วงก่อนส่ง
5. ผู้จัดรอบเปิดคะแนนที่ส่งแล้วให้แก้ได้ก่อนยืนยันผล ต้องกรอกเหตุผลและมีประวัติ
6. ผู้บริหารยืนยันผลเมื่อทุกคนส่งครบ ผลจึงปรากฏในฝ่ายบุคลากรและครูเจ้าของผล
7. พิมพ์สรุปหรือบันทึก PDF ผ่านหน้าผลที่ยืนยันแล้ว คะแนนในรอบที่ยืนยันแล้วแก้ไม่ได้

เกณฑ์ที่แก้จะสร้างแถวรุ่นใหม่เสมอ รอบประเมินเก็บ snapshot ไม่เปลี่ยนตามเกณฑ์รุ่นใหม่
คะแนนมี revision เพื่อป้องกันบันทึกทับจากหลายหน้าต่าง และตรวจสถานะอีกครั้งด้วย SQL ตอนบันทึก/ยืนยันผล
ลิงก์แฟ้มหลักฐานต้องเป็น HTTPS; ผู้จัดรอบต้องกำหนดสิทธิ์ไฟล์ที่ต้นทางให้กรรมการเอง ระบบไม่เปิด Drive ให้สาธารณะ

## ผู้ทรงคุณวุฒิภายนอก

- ใส่ชื่อและหน่วยงานให้ตรงกับผู้ที่แต่งตั้ง ระบบแสดงลิงก์ครั้งเดียวให้ผู้จัดรอบนำไปส่งเอง
- ลิงก์มี token สุ่ม 256 บิตใน URL fragment ไม่ถูกส่งใน query/referrer และฐานเก็บเฉพาะ SHA-256
- ใช้ลิงก์ครั้งแรกเพื่อออก host-only Secure/HttpOnly/SameSite=Strict cookie ไม่มีบัญชีโรงเรียน
- หมดอายุ 7 วันนับจากออกลิงก์ ไม่เลื่อนอายุตามการใช้งาน
- เห็นชื่อครู/เกณฑ์/ลิงก์หลักฐานเฉพาะรายที่มอบหมาย ไม่เห็นคะแนนกรรมการคนอื่นหรือทะเบียนครูทั้งหมด
- ออกลิงก์ใหม่ได้โดยระบุเหตุผล ทำให้ลิงก์และ session เก่าใช้ไม่ได้; เพิกถอนได้ทันที
- ลิงก์เป็นกุญแจเข้าถึง ผู้จัดรอบต้องส่งเฉพาะผู้ทรงคุณวุฒิที่ระบุ ไม่มีการส่งข้อความ/อีเมลอัตโนมัติ

## เกณฑ์ทางการและข้อจำกัดก่อนเปิดใช้จริง

แหล่งอ้างอิง:
- คู่มือ ว9/2564/ว22/2564: https://otepc.go.th/images/00_YEAR2564/03_PV1/w9_2564_24052564.pdf
- ว19/2568: https://circular.otepc.go.th/files/W19-2568_.pdf
- ประกาศและบทเฉพาะกาล: https://www.otepc.go.th/th/content_page/item/5503-w19-2568.html

แบบเริ่มต้นทุกแบบยังไม่ถูกบันทึกเป็นเกณฑ์ที่ยืนยันแล้วอัตโนมัติ:
- PA: โครงสร้าง 15 ข้อ × 4 = 60 + ประเด็นท้าทาย 20/10/10 = 40; กรรมการทุกคนต้องได้ ≥70% ไม่ใช้คะแนนเฉลี่ยตัดสินแทน
- ว19/2568: มีโครงสร้างแบบตรวจรายการแยกรอบ 1–2 และ 3–4; ยังเป็นรายการชั่วคราวที่ต้องกรอกแทนตามแบบฉบับเต็ม ระบบห้ามยืนยันเกณฑ์ที่ยังมีข้อความ “รอระบุรายการ”
- รายละเอียดรายการย่อย/เงื่อนไขการบันทึก ว19/2568 ยังอ่านไฟล์ฉบับเต็มไม่ได้ในสภาพแวดล้อมนี้ จึงไม่อ้างว่าตรงแบบทางการหรือพร้อมประเมินจริง
- รายที่เริ่มตาม ว19/2561/ว26/2561 อาจต้องใช้เกณฑ์เดิมตามบทเฉพาะกาล ผู้จัดเกณฑ์ต้องเลือกรุ่นให้ตรงกับรายบุคคล; ยังไม่มี seed แบบเดิมที่ยืนยันแล้ว
- ระบบรองรับคะแนนทุกคน, คะแนนเฉลี่ย, และจำนวนข้อผ่านรายด้าน แต่การสร้างเกณฑ์ใหม่เป็นการตั้งค่าของโรงเรียน ไม่ทำให้กลายเป็นแบบ ก.ค.ศ. อัตโนมัติ

ต้องได้ไฟล์แบบ PA และครูผู้ช่วยฉบับที่โรงเรียนใช้เพื่อตรวจระดับวิทยฐานะ รายการย่อย เงื่อนไข และตั้งเกณฑ์รุ่นแรกให้ครบก่อนเปิดรอบจริง
ระบบนี้ยังไม่รวม PA1/การเขียนข้อตกลง การลงนามดิจิทัล การรับรองคำสั่งแต่งตั้ง หรือการยื่น DPA
ผลบนระบบเป็นข้อมูลประกอบการพิจารณาของผู้มีอำนาจ ไม่มีการตัดสินสถานะการจ้าง/แต่งตั้งอัตโนมัติ
