# ทะเบียนคำร้องย้ายเข้า–ย้ายออก

Frontend source อยู่ใน `SATTASAI/dmcreport`; production build ถูกเก็บที่ `public/dmcreport/` และให้บริการผ่าน `/dmcreport/` ใช้บัญชี/session โรงเรียนเดิม เพื่อไม่ต้องแชร์รหัสผ่านหรือขยาย cookie ไปยัง subdomain ใหม่

API อยู่ที่ `src/routes/student-transfers.js` สร้างตารางเพิ่มใน binding DB เดิมเมื่อใช้งาน โดยไม่ลบหรือแก้ข้อมูลเดิม ไฟล์ใช้ Google Drive service เดิมและมีการตรวจชนิด/ขนาดไฟล์ก่อนอัปโหลด การเปิดไฟล์ตรวจสิทธิ์เจ้าหน้าที่/ผู้บริหารทุกครั้ง

Dashboard เพิ่มยอดคำร้องทุกปีการศึกษาและยอดอนุมัติย้ายเข้า/ออกจากตารางคำร้อง ใช้ revision triggers และ polling เดิม ไม่มีรายชื่อนักเรียนแสดงในสรุปสาธารณะ/บัญชีผู้ชม ครูทั่วไปและผู้ชมเข้า API คำร้องไม่ได้

การอนุมัติเป็นผลพิจารณาคำร้องเท่านั้น การปรับทะเบียนนักเรียนหลัก สถานะรายภาค และผลการเรียนยังดำเนินการในระบบรายงานผลการเรียนซึ่งเป็นเจ้าของข้อมูลตาม `grade-owned.js` ไม่มีการเปลี่ยน roster ซ้ำจากคำร้องนี้

สิทธิ์: superadmin เข้าใช้และตั้งค่าสิทธิ์ได้เสมอ บัญชีอื่นต้องมี explicit grant ใน student_transfer_access; บัญชีที่ได้รับสิทธิ์บันทึกและตรวจเอกสาร ส่วน executive ที่ได้รับสิทธิ์/superadmin อนุมัติหรือไม่อนุมัติ ต้องตรวจไฟล์ทั้ง 3 รายการครบก่อนอนุมัติ เปลี่ยนไฟล์แล้วผลตรวจเอกสารนั้นถูกรีเซ็ต สถานะสิ้นสุดล็อกการแก้ไข ประวัติการพิจารณาเก็บแยกและการแก้ไขใช้ version guard ภายใน batch เดียวกัน

ทดสอบ: `node --test tests/student-transfers.test.mjs tests/dashboard-live.test.mjs` และชุดทดสอบเดิมทั้งหมด Fixture ใช้ SQLite ในหน่วยความจำและ fake storage ไม่มีข้อมูลนักเรียนจริงหรือไฟล์ส่วนบุคคล


เมนูนักเรียนอยู่ใน iframe (?view=students-frame) อ่านเฉพาะข้อมูลพื้นฐานผ่าน /api/student-transfers/students ซึ่งตรวจสิทธิ์รายบุคคลเช่นเดียวกับคำร้อง ไม่เปิด API กลางให้ครูทุกคน

นำเข้า XLSX/CSV/JSON: frontend แปลงไฟล์เป็น rows (สูงสุด 200) จากนั้น /import/preview ตรวจข้อมูลก่อนแสดงตัวอย่าง และ /import ตรวจซ้ำก่อนบันทึก atomic พร้อม batch_ref + payload_hash กัน retry ซ้ำ แจ้งรายการผิดกลับ frontend ย้ายออกต้องตรงกับนักเรียนกำลังศึกษาในฐานกลาง การนำเข้าไม่แก้ roster และไม่อนุมัติจากไฟล์

บัญชีที่ไม่ได้รับสิทธิ์เข้า API คำร้อง เอกสาร นักเรียน และนำเข้าไม่ได้ มอบ/ถอนสิทธิ์บันทึก audit_logs เฉพาะแอดมินตั้งค่า ไม่มีการมอบสิทธิ์บัญชีจริงระหว่าง deploy


`GET /api/student-transfers/students/:id` อ่านนักเรียนที่เลือกด้วยสิทธิ์ทะเบียนย้ายเดิม คืนเฉพาะข้อมูลพื้นฐานเช่นเดียวกับตารางใน iframe เมื่อกดชื่อ frontend ตรวจ origin/source ของข้อความจาก iframe แล้วอ่านข้อมูลใหม่จาก endpoint นี้เพื่อเติมแบบฟอร์ม ยังต้องยืนยันบันทึกเอง และไม่เปลี่ยน roster อัตโนมัติ


รายชื่อนักเรียนรองรับ `sort=name|code|grade` และ `order=asc|desc` จัดเรียงก่อน LIMIT/OFFSET ทั้งชุด API ตรวจ whitelist ก่อนเลือก ORDER BY เลขประจำตัวชนิดตัวเลขใช้ค่าตัวเลข (2 ก่อน 10) แต่คืนเลขประจำตัวเดิม ระดับชั้นจัดกลุ่มอนุบาล ประถม มัธยม และจัดลำดับห้อง พร้อมคีย์ id ปิดท้ายให้การแบ่งหน้าแน่นอน

## หลักฐานแจ้งย้ายเบื้องต้นจากผู้ปกครอง

- แบบฟอร์มสาธารณะ `/transfer-notice.html` ไม่ต้องเข้าสู่ระบบ เก็บชื่อ–นามสกุลนักเรียน ประเภทย้ายเข้า/ออก โรงเรียนปลายทางเฉพาะย้ายออก เบอร์โทรผู้ปกครอง/ผู้มาติดต่อ และที่อยู่ที่ติดต่อได้
- เมื่อส่งสำเร็จออกเลขรับแจ้ง `TN-<UUID>` และวันเวลาจากฐานข้อมูล (UTC แสดงหน้าเว็บเป็นเวลาไทย) ผู้แจ้งบันทึกภาพหน้าจอหรือพิมพ์หลักฐานได้ ไม่มีหน้าค้นหาข้อมูลส่วนบุคคลสาธารณะ
- `POST /api/public/transfer-notices` บันทึกตาราง `student_transfer_notices` แยกจากคำร้องและทะเบียนนักเรียนหลัก ไม่สร้างคำร้อง ไม่อนุมัติ และไม่แก้ roster ครูผู้รับผิดชอบกรอกข้อมูลทะเบียนและเอกสารเองอีกครั้ง
- `client_ref` UUID กันส่งซ้ำ: ส่งซ้ำคืนเลขรับแจ้งและเวลาครั้งแรก ไม่แก้หลักฐานเดิม จำกัดเนื้อหา 8 KB ตรวจค่าทั้ง client/server ป้องกัน cross-origin และจำกัดการส่ง 20 ครั้ง/IP/ชั่วโมง (เก็บ hash ของ IP ผสมชั่วโมง ไม่เก็บ IP ตรง ๆ; ล้าง bucket หมดอายุเมื่อมีการส่งใหม่)
- เจ้าหน้าที่เปิด `/transfer-notices.html` จากแผงทะเบียนย้ายบน dashboard ดูรายการครั้งละ 50 รายการและบันทึกว่าครูรับทราบแล้วได้ สิทธิ์ใช้ explicit grant เดียวกับทะเบียนย้าย; การรับทราบไม่แก้ข้อมูลผู้แจ้งหรือวันเวลาต้นฉบับ และคงผู้รับทราบคนแรก
- QR Code `/transfer-notice-qr.svg` ชี้ไป `https://system.banpadengschool.ac.th/transfer-notice.html` มีปุ่มพิมพ์และดาวน์โหลดในหน้าเจ้าหน้าที่ สร้างไฟล์ไว้ในระบบ ไม่ส่งข้อมูลผู้ปกครองไปบริการสร้าง QR ภายนอก
- ทดสอบ `node --test tests/transfer-notices.test.mjs tests/student-transfers.test.mjs tests/transfer-access-import.test.mjs tests/dashboard-live.test.mjs`

## หน้าแจ้งย้ายในทะเบียนย้าย

- เปิด `/dmcreport/` แล้วเลือก “แจ้งย้าย” ข้อมูลหลักฐานเดิมมาจาก `GET /api/student-transfers/notices` ครั้งละ 50 รายการ เรียงยังไม่ตรวจสอบก่อน
- จุดแดงที่เมนูคงอยู่เมื่อ `GET /api/student-transfers/notices/summary` คืน `pending > 0` โดยนับจาก `acknowledged_at IS NULL` ทุกหน้า อัปเดตทุก 30 วินาทีและเมื่อกลับเข้าหน้าต่าง
- การเปิดอ่านไม่เปลี่ยนสถานะ ต้องกด “ตรวจสอบแล้ว” เพื่อเรียก `POST /api/student-transfers/notices/:id/acknowledge` คงผู้ตรวจและเวลาครั้งแรก ใช้สิทธิ์เดียวกับทะเบียนย้ายทุก endpoint
- รายการแสดงชื่อ ประเภทย้าย โรงเรียนปลายทาง เบอร์โทร ที่อยู่ เลขรับแจ้ง และวันที่แจ้ง ไม่สร้างคำร้องหรือเปลี่ยนทะเบียนหลัก
- Frontend source: [dmcreport commit](https://github.com/SATTASAI/dmcreport/commit/31bd06bef5cc62cf17b3f30ddba2ab9fe9855d8a) build แล้ว sync มาที่ `public/dmcreport/`

## แจ้งงานใหม่ผ่าน School Notify

- เมื่อบันทึกหลักฐานจากผู้ปกครองสำเร็จ Worker เรียก push dispatcher เบื้องหลัง และมี cron เดิมช่วยเก็บตก
- Feed ใช้ key `transfer-notice:<id>` ให้บัญชี active ที่มี explicit grant ใน `student_transfer_access` รวม superadmin ไม่รวมบัญชีถูกปิด/ลบ/ไม่มีบทบาท/ผู้ชม
- ส่งเฉพาะอุปกรณ์ที่ผูกกับบัญชีและเปิดรับ School Notify ตามการตั้งค่าเดิม หมวด `transfer` (“แจ้งย้ายนักเรียน”) URL `/dmcreport/?view=notices`
- ข้อความแจ้งเตือนมีประเภทย้ายและชื่อนักเรียน รายละเอียดติดต่ออ่านจากหน้าแจ้งย้ายหลังตรวจสิทธิ์
- ระบบเดิมเก็บข้อความใน `push_feed_messages`, จอง/กันซ้ำผ่าน `push_feed_sent` ต่อบัญชีและ key และลองใหม่เมื่อผิดพลาดชั่วคราว
- เปิดอ่านกระดิ่งไม่ยกเลิกการส่งรายการใหม่ จุดแดงและสถานะรอตรวจสอบยังคงอิง `acknowledged_at`; เมื่อมีเจ้าหน้าที่ตรวจสอบแล้วหรือถอนสิทธิ์ผู้รับ รายการจะไม่เข้า feed เพื่อส่งอีก
- การเพิ่มนี้ใช้ School Notify ไม่เพิ่มการส่ง LINE สำหรับแจ้งย้าย
