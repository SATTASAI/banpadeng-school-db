# สำรองไฟล์ Google Drive และทดสอบกู้คืน

หน้าผู้ดูแลระบบ **ความปลอดภัยและสำรองข้อมูล → สำรองไฟล์ Google Drive** ดาวน์โหลดไฟล์ที่ลงทะเบียนไว้ใน `file_attachments` เฉพาะรายการ `storage_provider='drive'` ลงโฟลเดอร์ที่ผู้ดูแลเลือกบนคอมพิวเตอร์ ใช้ Chrome หรือ Edge เวอร์ชันที่รองรับการเลือกโฟลเดอร์

1. ส่งออกฐานข้อมูล D1 แยกไว้ด้วย เพื่อเก็บทะเบียนและความสัมพันธ์กับเอกสาร
2. กด **เลือกโฟลเดอร์และเริ่มสำรองไฟล์** แล้วเลือกพื้นที่ที่โรงเรียนควบคุมสิทธิ์ ระบบจะสร้างโฟลเดอร์ใหม่ชื่อ `banpadeng-drive-backup-...` ภายในนั้น
3. รอจนขึ้น **สำรองครบ** และตรวจ `manifest.json` ว่า `complete` เป็น `true` ส่วนไฟล์จริงอยู่ใน `files/`
4. ย้ายสำเนาทั้ง D1 และไฟล์ไปยังพื้นที่ที่แยกจาก Google Drive ต้นทางและจำกัดผู้เข้าถึง เพราะอาจมีข้อมูลส่วนบุคคล

ระบบจับขอบเขตทะเบียนไฟล์ ณ เวลาเริ่มงาน ดาวน์โหลดไฟล์ทีละรายการ และตรวจขนาดกับ SHA-256 เดิมเมื่อมีข้อมูล หากมีไฟล์หาย ถูกแก้ระหว่างสำรอง ดาวน์โหลดล้มเหลว หรือปิดหน้าเว็บกลางคัน **ห้ามถือว่าเป็นสำเนาที่สมบูรณ์** เริ่มใหม่ในโฟลเดอร์ใหม่และตรวจรายการปัญหาในหน้าเว็บ/`manifest.json` ห้ามลบต้นฉบับจากผลสำรองนี้

## ตรวจไฟล์และจำลองการกู้คืน

ใช้ Node.js กับสำเนาที่ดาวน์โหลดมา (ไม่ต้องใช้รหัสผ่าน Google หรือไฟล์ฐานข้อมูล):

```sh
node scripts/verify-drive-backup.mjs "/path/to/banpadeng-drive-backup-..."
node scripts/verify-drive-backup.mjs "/path/to/banpadeng-drive-backup-..." --restore-to "/path/to/new-restore-test"
```

คำสั่งแรกตรวจไฟล์ทุกรายการและ hash; คำสั่งที่สองคัดลอกไปยังโฟลเดอร์ทดสอบ **ที่ยังไม่มีอยู่** แล้วอ่านตรวจอีกครั้ง ไม่เขียนไป Google Drive หรือ D1 จริง หากสำเนาไม่ครบหรือไฟล์ผิด จะจบด้วย error

ขอบเขต: ระบบสำรองเฉพาะไฟล์ Drive ที่มีทะเบียนใน D1 ณ เวลาที่เริ่ม ไม่รวมไฟล์ Drive ที่ไม่มีทะเบียน ไฟล์เดิมใน R2 หรือประวัติเวอร์ชันเก่าของ Drive สำรอง SQL ของ D1 ต้องเก็บแยกต่างหาก หากมีการเปลี่ยนไฟล์หลังสำรอง ให้สำรองรอบใหม่ก่อนนำสำเนาไปกู้คืนจริง
